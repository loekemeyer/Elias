## Nota sobre el panel admin

`admin.js` siempre corre con sesion de admin: cada pagina de admin redirige a `mayorista.html` si
`auth_user_id` no esta en `admins` (convencion documentada en el `CLAUDE.md` de PaginaLK). O sea
que el guard A no puede dejar afuera al panel — cuando el panel llama, la sesion ya paso por ese
mismo chequeo.

Excepcion a mirar: `admin.js:6832` usa `get_all_sales_lines_admin` como **fallback profundo** dentro
de un `try/catch` en cascada. Si el guard hace `RAISE`, el catch lo absorbe y sigue al fallback
siguiente. Comportamiento aceptable, pero registrarlo: para un admin legitimo esa RPC debe
responder con datos, no caer al catch.

## Estado de `sales_lines`

legitimamente. **0 filas para un admin no es falla; excepcion para un anon si es exito.** No
confundir los dos casos al interpretar los resultados.
